## 1. Введение и постановка задачи

- **Цель проекта:** предсказать итоговую сумму покупки в ювелирном интернет магазине. Это полезно для магазина, потому что можно прогнозировать выручку и формировать персональные предложения
- **Формулировка задачи:** регрессия
- **Обоснование метрики качества:**
  - **MAE** — средняя абсолютная ошибка, показывает ошибку в тех же единицах, устойчива к выбросам
  - **RMSE** — штрафует за большие ошибки, полезна для понимания худших случаев
  - **R<sup>2</sup>** — показывает, какую долю дисперсии цены объясняет модель

---

## 2. Поиск и описание данных

- **Источник:** датасет [eCommerce purchase history from jewelry store](https://www.kaggle.com/datasets/mkechinov/ecommerce-purchase-history-from-jewelry-store) с Kaggle. Я выбрал эту тему, потому что так было проще сделать уникальный проект, а также данные покрывают около трёх лет покупок
- **Описание датасета:**
  - Объём: 95 910 строк и 13 столбцов
  - Данные не имели заголовков — были восстановлены вручную

| Признак | Описание | Тип |
|---|---|---|
| `event_time` | Дата и время события | Строка (datetime) |
| `order_id` | ID заказа | int64 |
| `product_id` | ID товара | int64 |
| `quantity` | Количество единиц в заказе | int64 |
| `category_id` | ID категории | int64 |
| `category_alias` | Псевдоним категории (напр. `jewelry.ring`) | str |
| `brand_id` | ID бренда | int64 |
| `price` | Цена в USD — **целевая переменная** | float64 |
| `user_id` | ID пользователя | int64 |
| `gender` | Пол покупателя (`f` / `m`) | str |
| `color` | Основной цвет изделия | str |
| `metal` | Тип металла (gold, silver…) | str |
| `gem` | Тип камня (diamond, sapphire…) | str |

## 3. Обработка и подготовка данных

- **Полная очистка:**
  - **Заголовки:** датасет не имел имён столбцов, были добавлены вручную
  - **Типы данных:** числовые колонки с некорректными значениями, которые попали строки из-за сдвига данных, приведены к `Int64` / `float64`; строковые — к `str`
  - **Дубликаты:** удалены через `drop_duplicates()`
  - **Пропуски:**
    - Строки без `price`, `order_id`, `user_id`, `product_id`, `event_time` — удалены
    - Строковые признаки (`category_alias`, `gender`, `color`, `metal`, `gem`) — заполнены значением `"unknown"`
    - `brand_id`, `category_id` — заполнены значением `-1`, обозначающее неизвестное значение
    - `quantity` — заполнен `1` как значение по умолчанию
  - **Выбросы по цене:** применена двухэтапная фильтрация:
    - Удалены значения за пределами +-2σ от среднего
    - Метод Тьюки: удалены значения ниже Q1 − 1.5·IQR и выше Q3 + 1.5·IQR
- **Работа с фичами:**
  - Исходное количество признаков: 13
  - Новые фичи:
    | Новый признак | Смысл |
    |---|---|
    | `month` | Месяц события |
    | `day_of_week` | День недели |
    | `is_weekend` | 1, если суббота или воскресенье |
    | `is_holiday_season` | 1, если месяц 12, 2 или 3, потому что в эти месяцы Новый год, 14 февраля, 8 марта |
  - Смысл: ювелирные украшения часто покупают к праздникам, поэтому сезонные признаки должны быть информативны
- **Визуализации:** 
  - Карта корреляций — показывает, что линейных зависимостей почти нет, отсюда вывод о необходимости нелинейных моделей
  - Boxplot по категориальным признакам (`metal`, `gem`, `gender`) — видно, что металл и камень заметно влияют на медианную цену
- **Сплит данных:**
  - Train - 70%, Validation - 15%, Test - 15%
  - Данные отсортированы по `event_time` для предотвращения утечки данных

- **Результаты:**

## 5. Эксперименты

### Гипотеза 1: древовидные модели лучше линейных

Корреляционная матрица показала отсутствие линейных зависимостей значит пробуем Decision Tree и ансамблевые методы

| Модель | MAE | RMSE | R<sup>2</sup> | Комментарий |
|---|---|---|---|---|
| Linear Regression (baseline) | 141.56$ | 178.52$ | −0.013 | Не справляется с нелинейностью |
| Decision Tree | 102.40$ | 137.91$ | 0.419 | Большой прирост качества |
| **Random Forest** | **100.09$** | **135.10$** | **0.442** | **Усреднение деревьев помогает** |
| Gradient Boosting | 103.08$ | 136.47$ | 0.431 | Чуть хуже RF |
| **Hist Gradient Boosting** | **100.70$** | **133.71$** | **0.454** | Лучший из базовых |
| XGBoost | 101.28$ | 134.78$ | 0.445 | Близко к HGB |
| LightGBM | 101.66$ | 134.74$ | 0.445 | Близко к HGB |

**Результат:** все древовидные модели существенно превосходят baseline. Hist Gradient Boosting и Random Forest оказались лучшими


### Гипотеза 2: подбор гиперпараметров улучшит качество

Использован `RandomizedSearchCV`. Перебирались параметры:
- **Random Forest:** `n_estimators`, `max_depth`, `min_samples_leaf`
- **Hist Gradient Boosting:** `max_iter`, `max_depth`, `learning_rate`

| Модель | MAE | RMSE | R<sup>2</sup> | Параметры |
|---|---|---|---|---|
| Random Forest (Tuned) | 99.13$ | 134.64$ | 0.446 | n_estimators=200, max_depth=15, min_samples_leaf=5 |
| **Hist Gradient Boosting (Tuned)** | **98.94$** | **132.60$** | **0.463** | max_iter=200, max_depth=12, learning_rate=0.1 |

**Результат:** подбор гиперпараметров дал небольшое, но стабильное улучшение. Лучшей стала Hist Gradient Boosting

## 6. Финальная модель и интерпретируемость

- **Обоснование выбора финальной модели:** `HistGradientBoostingRegressor` с параметрами `max_iter=200`, `max_depth=12`, `learning_rate=0.1`, потому что лучший MAE (98.94) и RMSE (132.60) среди всех моделей
- **Интерпретируемость:**
  - Категориальные признаки `metal`, `gem` и `gender` сильнее всего влияют на медианную цену, что видно из boxplot
  - Корреляционная матрица подтверждает, что нелинейные методы подходят лучше
